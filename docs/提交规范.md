# 提交规范（Conventional Commits）

本项目所有 Git 提交必须遵循 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/zh-hans/v1.0.0/)。
理由是任务书验收 6 要求"提交记录体现本人真实开发过程"，规范化提交才能让评审一眼看出每周做了什么。

## 一、格式


<type>(<scope>): <subject>

<body>

<footer>


- 第一行 `type(scope): subject` **必填**，整行不超过 72 个字符。
- subject 用中文，**不加句号**，动词开头，说清"做了什么"而不是"改了一些东西"。
- body 可选，说明**为什么**这么做（不是重复 subject）。每行不超过 72 字符。
- footer 可选，写 `Refs: #12`、`BREAKING CHANGE: ...` 等。

## 二、type 取值（只用这 11 个）

| type | 用途 | 示例 |
| :--- | :--- | :--- |
| `feat` | 新增功能 | `feat(chat): 支持流式返回并标注出处` |
| `fix` | 修 bug | `fix(rag): 修正余弦相似度未归一化导致 Top-1 偏差` |
| `docs` | 只动文档 | `docs(topic): 补选题卡语料来源表` |
| `style` | 格式调整，不改逻辑 | `style(web): 统一 Prettier 缩进` |
| `refactor` | 重构，不改行为 | `refactor(memory): 抽出用户档案读写模块` |
| `perf` | 性能优化 | `perf(retrieval): 向量预归一化，检索耗时降 60%` |
| `test` | 测试相关 | `test(safety): 补 10 题危机话术用例` |
| `build` | 构建/依赖 | `build(server): 升级 express 到 4.21` |
| `ci` | CI 配置 | `ci: 加 eslint 与 tsc 检查` |
| `chore` | 杂项（脚手架、gitignore） | `chore: 初始化 web + server 工程骨架` |
| `revert` | 回滚 | `revert: feat(chat): 支持流式返回并标注出处` |

## 三、scope 取值（本项目约定）

`web` / `server` / `rag` / `memory` / `safety` / `corpus` / `topic` / `deploy` / `docs`

不确定时省略括号，不要自造 scope。

## 四、提交粒度

1. **一次提交只做一件事。** 搭骨架和写选题卡不能塞进同一条。
2. **禁止 `update`、`修改`、`提交`、`fix bug` 这类无信息量的 subject。**
3. 每周至少 1 条有意义的提交；W7 答辩前 `git log --oneline` 应当能读出完整时间线。
4. 禁止一次性倾倒代码（任务书验收 6 明文禁止）。

## 五、怎么提交（本项目实操）

本工作区**不允许**在命令里使用 `cd` 与 `&&`，且多行提交信息直接写在命令行容易出错。
因此统一采用 **提交信息文件 + `git commit -F`** 的方式：

1. 把提交信息写进 `docs/commits/<周次>-<序号>-<短名>.txt`，例如 `docs/commits/w1-1-skeleton.txt`。
2. 暂存目标文件：`git add <具体路径>`（不要用 `git add -A`）。
3. 从文件读取信息提交：`git commit -F docs/commits/w1-1-skeleton.txt`。

`-F` 会原样读取文件内容（含空行），第一行作为 subject，空行之后的段落自动成为 body，无需处理换行转义。

> 提示：提交信息文件本身也纳入版本管理，答辩时可连同 `git log` 一起展示，作为"提交有规划"的旁证。

## 六、示例


chore: 初始化 web + server 工程骨架

- web: Vue3 + Vite + TS（strict），ESLint 9 flat config + Prettier
- server: Express + TS，提供 /api/health 健康检查
- corpus/: 建立语料目录与写作规范占位
- docs/: 落地提交规范，后续每周沿用

Refs: 任务书约束 1、验收 6
